# Security, runtime and licensing boundary

Target environment is Windows 10/11 x64, Python 3.12 and Node 22. Pin browser/runtime dependencies and review lockfiles before C2; frontend hosts only on loopback in released local mode. Credentials remain OS/user configuration inputs, are never committed/logged, and are passed through redaction helpers. G-Labs calls are paid operations: prepare/estimate first, explicit scoped confirmation second, immutable consent/attempt records third; ambiguous submission is reconciled, not retried.

Windows child processes require a supervisor, bounded stdout/stderr, cancellation, Job Object/process-tree cleanup, timeouts and durable ownership fencing. Artifact roots must use resolved containment checks, reject absolute/traversal paths and symlink/reparse-point escapes, stream hashes, and never delete referenced bytes. SQLite uses foreign keys, WAL, bounded busy timeout, one write owner and no open transaction over network/large files; recovery only reconciles owned attempts.

## Spine G1 license evidence (C0 research boundary)

Official Spine documentation states that runtime/data and editor major/minor versions must match, and the official `spine-pixi-v8` integration requires PixiJS 8.16 or later. G1 must pin a compatible Spine 4.2 runtime/data pair and exact Pixi release. Runtime/editor use and distribution are governed by Spine's runtime/editor license terms; an npm package installation is not proof of redistribution/commercial rights. Before G1, the operator must verify the intended editor seats, runtime integration/distribution use, asset ownership, and end-user distribution against the official sources: [versioning](https://en.esotericsoftware.com/spine-versioning), [Pixi runtime](https://en.esotericsoftware.com/spine-pixi), [runtime license](https://en.esotericsoftware.com/spine-runtimes-license), [editor license](https://us.esotericsoftware.com/spine-editor-license). C0 records this as a license gate, not a feasibility PASS.
